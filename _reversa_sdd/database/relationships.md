# Database Relationships — GER

> Generated by Reversa (Data Master) on 2026-04-28
> Phase: Revisão (Agente Independente)

O ecossistema de dados do GER adota uma arquitetura **Polyglot Persistence** desacoplada:

## 1. Isolamento Físico
- **SQLite (`gercon_raw_data.db`)**: Gerencia o estado efêmero do Scraper, watermarks e auditorias técnicas.
- **DuckDB/Parquet**: Armazena os dados limpos agregados para queries OLAP de alta velocidade na UI.

## 2. Relações Lógicas (Soft Constraints)
Embora não existam Constraints físicas (`REFERENCES`) entre os arquivos, o sistema assume integridade referencial via domínio:

### `solicitacoes_raw` <--> `gercon`
- **Cardinalidade**: 1:1
- **Chave de Junção**: `solicitacoes_raw.protocolo` == `gercon.numeroCMCE`
- **Fluxo**: O pipeline de ETL extrai o `conteudo_json` do SQLite, normaliza os campos e exporta o arquivo Parquet que serve a view `gercon`.

### `ingestion_logs` e `dead_letter_queue`
- **Escopo**: Entidades de suporte técnico. Não se relacionam diretamente com entidades clínicas de negócio.
