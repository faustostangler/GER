# ADR-006: IAM Zero-Trust & CRM Domain Authorization

> Generated by Reversa (Detective) on 2026-04-28
> Level: Detailed

## Context
Authentication (handled by Keycloak) only verifies user identity, not professional medical credentials. Accessing clinical data requires strict verification against the CFM (Federal Medical Council).

## Decision
Implement a Zero-Trust gate in the domain entity `DoctorProfile`. Authorization requires `crm_verified=True`, updated via an asynchronous Kafka consumer upon CFM validation.

## Alternatives Considered
1. **JWT Claims**: Trusting roles injected by Keycloak (insecure, as Keycloak lacks medical registry authority).
2. **Synchronous API Calls**: Querying CFM in real-time (slow and introduces external single point of failure).

## Consequences
- **Positive**: Robust security posture; decoupled architecture.
- **Negative**: Eventual consistency in onboarding flows (users must wait for sync).
